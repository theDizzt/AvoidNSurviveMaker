# 도전과제 시스템 설계안

상태: 1차 기능 구현 완료. 2차 이벤트형 과제는 후속 설계다.

## 적용 안내

- 메인 메뉴 → 도전과제에서 12개 과제, 필터, 진행도, 남은 대상 레벨, 챕터 이동을 제공한다.
- 로컬 해금은 바로 동작한다. 계정 기록 조회는 기존 테이블을 사용한다.
- 계정의 영구 해금·기기 간 달성일 동기화를 사용하려면 `supabase/migrations/20261119010000_achievements.sql`을 기존 마이그레이션 다음에 적용한다. 이번 작업에서 원격 DB에는 적용하지 않았다.
- 마이그레이션 적용 전 또는 네트워크 오류 시 계정 도전과제는 로컬에 보존되고 ‘동기화 대기’로 표시된다. 연결 복구·기록 업로드·도전과제 화면 진입 시 재시도한다.
- 기존 브라우저 기록은 첫 비로그인 초기화 때 한 번 가져온다. 기존 저장 형식에는 소유자 정보가 없으므로 이 이력은 브라우저 기록으로 취급한다. 로그인한 계정에는 본인 서버 기록과 본인 미전송 기록만 사용한다.
- 실제 클리어에서 새로 얻은 과제는 결과 시점에 알린다. 기존 기록 소급분은 목록의 NEW 표시로 확인하며, ‘새 항목 확인 완료’로 읽음 처리한다.
- 현재 구현은 원본 기록에서 진행도를 재계산하고, 계정별 로컬 기록 캐시와 해금 상태를 저장한다. 서버 정의는 마이그레이션의 고정 목록과 `src/core/achievements.ts`를 함께 관리한다.
- 사용자의 요청에 따라 자동 테스트와 플레이 테스트는 실행하지 않았다. TypeScript 타입 검사만 수행했다.

아래는 상세 설계이며, `source` 메타데이터·백필 요약 알림·자동 정의 생성은 아직 적용하지 않은 후속 개선 사항이다.

## 1. 목표와 범위

플레이어가 첫 성공 → 여러 레벨 탐험 → 별 수집 → 기록 개선으로 자연스럽게 진행하도록 돕는다. 제작 활동은 별도 분류로 확장한다.

- 도전과제는 영구 해금한다. 맵 추가나 밸런스 변경으로 이미 획득한 과제를 회수하지 않는다.
- 1차 보상은 배지와 달성 이력이다. 별·챕터 해금 조건·충돌 판정에는 영향을 주지 않는다.
- 일일 접속, 방치 시간, 반복 사망을 필수 목표로 만들지 않는다.
- 1차는 기존 최고 기록에서 판정할 수 있는 과제만 출시한다. 연속 성공·제작 과제는 2차다.
- 공식 플레이 과제에는 커스텀 팩, 공유 맵, 에디터 테스트를 포함하지 않는다.

## 4. 화면과 알림

- 상단: `달성 4 / 12`, 전체 완료율, 저장 위치(이 브라우저 / 계정), 동기화 상태.
- 필터: 전체 / 진행 중 / 달성 완료. 분류는 클리어 / 별 수집 / 챕터, 추후 제작 추가.
- 카드: 배지, 이름, 조건, 진행 막대, `7 / 10`, 달성일. 달성 여부를 색만으로 구분하지 않는다.
- 기본 정렬: 진행 중 과제의 달성률 높은 순 → 완료 과제의 최근 달성 순. 동률은 정의 순서 유지.
- 상세: 대상 챕터, 남은 레벨, 집계 제외 조건. ‘도전하기’는 미완료이면서 접근 가능한 레벨 선택 화면으로 이동한다.
- 진행 중에는 클릭 영역·중앙 시야를 가리는 팝업을 띄우지 않는다. 클리어 결과 화면에서 `도전과제 달성: 첫 생존`을 표시한다.
- 한 번에 여러 개를 획득하면 최대 3개를 표시하고 나머지는 `외 n개`로 묶는다. 새 항목 표시는 목록을 확인할 때 해제한다.
- 기존 기록 소급 적용·다른 기기 동기화 시에는 개별 팝업 대신 `기존 기록으로 도전과제 n개를 달성했습니다`로 묶는다.
- 키보드 이동, 스크린 리더용 진행값, 모션 감소 옵션, 한·영·중 번역을 제공한다.

## 5. 판정 모델

정의와 사용자 상태를 분리한다. 1차 진행도는 원본 레벨 기록에서 계산하고 중복 저장하지 않는다.

```ts
type AchievementRule =
  | { kind: 'clearedLevels'; levelKeys: readonly string[]; target: number }
  | { kind: 'totalStars'; levelKeys: readonly string[]; target: number }
  | { kind: 'threeStarLevels'; levelKeys: readonly string[]; target: number }
  | { kind: 'allLevels'; levelKeys: readonly string[] };

interface AchievementDefinition {
  id: string; // 출시 후 의미와 조건을 변경하지 않음
  category: 'clear' | 'stars' | 'chapter';
  nameKey: string;
  descriptionKey: string;
  icon: string;
  order: number;
  rule: AchievementRule;
}

interface AchievementUnlock {
  id: string;
  unlockedAt: string; // 최초 판정 시각, 과거 실제 달성 시각으로 추정하지 않음
  source: 'live' | 'backfill';
  seenAt?: string;
}
```

순수 함수 `evaluateAchievements(definitions, records, previousUnlocks)`가 진행도와 신규 달성 ID를 반환한다. 시간·저장·알림은 호출자가 담당한다. 판정 자체는 맵, DOM, 네트워크를 변경하지 않는다.

판정 규칙:

1. 정의에 포함된 공식 키만 선택한다. 문자열 접두사만 보고 공식 레벨로 인정하지 않는다.
2. 유효한 최고 시간이 있으면 별이 0개여도 클리어로 센다.
3. 별은 레벨별 최고값을 0–3으로 제한해 합산한다. 중복된 `levelKeys`는 제거한다.
4. 이미 해금한 ID는 재발급하지 않는다. 화면 진행값은 목표치로 제한한다.
5. 기존 `pastel/` → `workshop/` 이관 기록은 같은 레벨로 처리한다.

판정 시점은 앱의 저장 데이터 로드 후, 공식 레벨 클리어 저장 후, 계정 로그인·기록 동기화 후다. 매 프레임 검사하지 않는다.

`progress.ts`의 `setOnRecord()`는 단일 콜백이며 현재 `RecordSync`가 사용 중이다. 도전과제가 이 콜백을 덮어쓰지 않도록 구독자 목록 방식으로 바꾸거나 `main.ts`에서 저장 후 판정을 명시적으로 호출한다. 다운로드 병합은 별도 완료 지점에서도 판정한다.

## 6. 저장·계정·오프라인

### 로컬

- 키: `avoid-n-survive:achievements:v1:guest`, `avoid-n-survive:achievements:v1:<userId>`.
- 저장 내용: 스키마 버전, 해금 목록, 알림 확인 상태. 파싱 실패 시 빈 상태로 복구하고 유효한 원본 기록으로 재계산한다.
- 저장 용량 초과·차단 시 메모리 상태로 계속 작동하고 ‘이번 세션에만 저장됨’을 표시한다.
- 게스트와 각 계정의 상태를 분리한다. 로그아웃은 계정 데이터를 게스트로 복사하지 않는다.

### 계정

현재 캠페인 로컬 기록은 계정별로 분리되어 있지 않다. 로그인 시 `allRecords()` 전체로 계정 도전과제를 판정하면 이전 사용자의 기록을 가져올 수 있다. 계정 판정에는 서버의 본인 기록 + 현재 계정에 귀속된 미전송 기록만 사용한다.

- 게스트 기록 가져오기는 기존 ‘기록 동기화’의 명시적 동작을 따른다. 도전과제 ID를 그대로 가져오지 않고, 수락된 기록으로 다시 판정한다.
- 계정 변경 시 진행 중 응답에 사용자 ID/요청 세대가 일치하는지 확인해 다른 계정 화면에 적용하지 않는다.
- 오프라인 클리어는 계정별 미전송 기록에서 즉시 로컬 달성 처리하고 ‘동기화 대기’로 표시한다. 서버 확정 상태와 구분한다.
- 재접속 시 기록 업로드 → 서버 판정 → 해금 목록 병합 순서로 처리한다. 일시적 조회 실패를 기록 없음으로 취급하지 않는다.

## 7. 2차 확장

| 후보 | 정확한 조건 | 추가로 필요한 데이터 |
|---|---|---|
| 다시 일어서기 | 같은 공식 레벨에서 한 플레이 세션 중 실제 사망 10회 후 클리어 | 세션 ID, 레벨 키, 사망·클리어 이벤트 |
| 흔들림 없는 손 | 사망·중단 없이 서로 다른 공식 레벨 3개 연속 클리어 | 도전 시작·종료 이벤트, 연속 성공 레벨 집합 |
| 어제보다 빠르게 | 기존 기록이 있는 공식 레벨 5개에서 자신의 최고 시간 갱신 | 갱신 전 기록, 서로 다른 개선 레벨 집합 |
| 첫 설계도 | 에디터에서 만든 초안을 테스트 클리어하고 내보내기 완료 | 초안 생성 출처, 테스트 검증, 내보내기 성공 이벤트 |
| 곡선의 설계자 | 직선·곡선 구간이 섞인 이동 오브젝트를 넣은 초안을 테스트 클리어 | 초안 출처, 검증된 맵의 `segmentTypes` 분석 |

연속 성공은 실제 게임 사망, 포커스 상실·창 이탈 등 도전 중단, 미완료 상태에서 레벨 변경, 앱 재시작 시 초기화한다. 완료 후 메뉴 이동은 유지한다. 사망 통계에서 중단을 제외하는 기존 정책과는 구별한다.

2차 이벤트는 `{ eventId, actorId, runId, type, levelKey?, occurredAt, payloadVersion }` 형태로 기록한다. 같은 이벤트 ID는 한 번만 반영하고, 순서가 필요한 과제는 세션 내 순번까지 사용한다. 다른 기기의 연속 성공 기록은 이어 붙이지 않는다. 서버 재시도 중복 집계 방지를 먼저 구현한 뒤 누적 이벤트 과제를 출시한다.

에디터 테스트는 플레이 과제에서 제외하되 제작 과제에는 사용한다. 불러온 맵을 단순히 재저장하는 행위와 새 초안 생성은 구분한다. 기존 기록으로 알 수 없는 실패 횟수·성공 순서·제작 이력은 소급 부여하지 않는다.

## 8. 구현 순서와 완료 기준

1. 공식 대상 레벨 목록을 고정하고 12개 정의·번역·순수 판정 함수 작성.
2. 로컬 저장 및 기존 기록 백필, 도전과제 화면, 결과 화면 알림 구현.
3. 계정별 기록 경계와 미전송 기록 접근을 정리한 뒤 DB/RPC 및 동기화 연결.
4. 경계 사례 검증 후 출시. 이벤트형·꾸미기 보상은 후속으로 분리.

예상 파일: `src/core/achievements.ts`, `src/core/achievements.test.ts`, `src/web/achievements.ts`, `src/web/achievements-ui.ts`, `src/web/auth/achievements.ts`, 신규 Supabase 마이그레이션. 기존 연결 파일은 `main.ts`, `progress.ts`, `index.html`, `style.css`, 세 언어 로케일이다.

필수 검증:

- 0별 클리어, 동일 레벨 재클리어, 최고 별 갱신, 시간만 개선되는 경우.
- 커스텀·공유·에디터 테스트 제외, 빈 챕터 제외, 중복·이관 키 처리.
- 기존 기록 백필, 반복 판정·동기화 시 해금 및 알림 중복 방지.
- 계정 A → 로그아웃 → 계정 B에서 기록·해금이 섞이지 않음.
- 오프라인·재접속·저장 실패·서버 실패·다중 기기에서 기록 유지.
- 콘텐츠 추가 후 기존 과제 분모·해금 유지, 대상 삭제 시 보관 정책 적용.
- 키보드·작은 화면·긴 번역 문구, 플레이 중 입력·시야 방해 없음.

출시 기준은 1차 과제가 모두 실제 달성 가능하고, 기록 재동기화로 추가 달성이 중복 발생하지 않으며, 다른 계정의 기록으로 과제가 해금되지 않는 것이다.
